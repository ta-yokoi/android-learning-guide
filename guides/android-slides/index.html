      1. AOSPはAndroidの基本となる公開ソースです。

      SLIDE 4 / 32

      アプリの起動と、処理する場所

      起動要求Zygoteアプリプロセスメインループ
      1. システムが、必要なアプリプロセスの起動を判断します。
      2. Zygoteをもとに、アプリ用プロセスが生成されます。
      3. ARTの実行環境で、アプリのコードが動きます。
      4. メインスレッドが入力や画面更新などを順に処理します。

      ARTは最後に呼ぶ独立した処理段階ではなく、コードの実行を支える環境です。メインスレッドで長いI/Oを行うと、入力や描画の処理が待たされます。プロセスとスレッドを区別してください。

      確認問題：重い通信をメインスレッドで待つと、なぜ画面が固まる？

      解答：同じスレッドの入力・描画などが処理できなくなるためです。非同期にし、結果を適切なスレッドへ戻します。

      SLIDE 5 / 32

      別プロセスへ、要求が渡る

      呼び出し側Proxy / Binderサービス結果 / 通知
      1. 呼び出し側がAIDLなどの契約に従って要求します。
      2. Binderを通して、別プロセスの境界を越えます。
      3. 受け手が権限や引数を検査し、要求を処理します。
      4. 戻り値と、後から届く通知を区別して受け取ります。

      同期呼び出しは相手の応答を待つため、呼び出すスレッドに注意します。onewayでも処理の成功や実機反映が保証されるわけではありません。サービス死亡や再接続も設計に含めます。

      確認問題：onewayにすれば、相手の処理は必ず成功する？

      解答：いいえ。待ち方が変わるだけで、処理結果の保証とは別です。必要なら結果通知や状態の再取得を用意します。

      画面の入口と、戻る先を分ける

      Intent解決する相手Activityバックスタック
      1. Intentが、行いたい操作や対象を表します。
      2. システムが条件に合う受け手を解決します。
      3. Activityが画面の入口となり、状態に応じて動きます。

      解答：なりません。実行するスレッドを別途設計する必要があります。Serviceは処理の役割と寿命に関するコンポーネントです。

      画面の状態と、保存の寿命

      onCreateonStartonResumeonPause / Stop
      1. 画面の作成時に、必要な初期化と復元を行います。
      2. 画面が見える状態へ進みます。
      3. 操作可能な前面の状態になります。

      解答：できません。コールバックが保証されない終了があります。必要な状態を適切な時点と保存先へ記録します。

      起動完了と、ユーザーの準備

      BootloaderKernel / initSystemServerユーザーの解錠
      1. 起動するイメージの選択や検証を経て進みます。
      2. Kernelとinitが、OSの土台とサービスを立ち上げます。
      3. システムサービスやアプリの実行環境が準備されます。
      4. ユーザーの解錠状態により、利用できるデータが変わります。

      図は起動経路の一部です。Device Encrypted領域とCredential Encrypted領域では利用できる時点が異なります。BOOT_COMPLETEDを受けたことと、製品で必要な全機能の準備完了は同じではありません。

      確認問題：OSが起動したら、ユーザーの全データをすぐ読める？

      解答：解錠前に利用できないデータがあります。ユーザー状態と保存領域の条件を分けて扱います。

      SLIDE 9 / 32

      画面OFFと、休止は同じではない

      画面OFF制約の確認休止できる条件復帰後の再確認
      1. 画面が消えても、処理や通信が続く場合があります。
      2. WakeLockやOSの制約、ハードウェア状態を確認します。
      3. 条件が整ったときに、サスペンドへ進める場合があります。
      4. 復帰後は接続や機能の状態をもう一度確かめます。

      画面、Androidの電源状態、Kernelのサスペンド、ホストOSや車両の状態は別の軸です。Dozeと物理サスペンドも同一ではありません。保持すべき処理には理由と解放条件が必要です。

      確認問題：画面OFFを検出したら、通信も止まったと断定できる？

      解答：できません。画面と通信の状態は別です。対象のネットワークや処理の状態を観測します。

      症状から、証拠へ進む

      症状時刻 / PIDログ / トレース仮説の検証
      1. 固まり、終了、再起動など、現象を区別します。
